# Memory Architecture — память агента под правильный рантайм (канон 2026-07-20)

> **Эта версия заменяет прежнюю (до 2026-07-20).** Старая модель — «memory.md пишет агент
> сам после задач» — УБИТА как канон-баг: эфемерный субагент умирает в момент возврата
> отчёта, шаг «после задачи» не наступает никогда. Подтверждено аудитом офиса из 14 агентов:
> живая память только у 2 — и оба работают в основной сессии, не субагентами.
> Формула канона: **промпт просит — хук/харнесс гарантирует.**

Демиург обязан читать этот файл перед проектированием памяти любого агента.

---

## Шаг 0. Сначала рантайм, потом память

Вопрос INTAKE «где агент будет жить?» — определяет весь протокол памяти:

| | **Эфемерный субагент Claude Code** | **Долгоживущий ТГ-бот (tg-agent-runtime)** |
|---|---|---|
| Контекст | свежий и изолированный на каждый вызов; умирает при возврате summary | живёт между сообщениями; kill по неактивности, мозг на диске остаётся |
| Самозапись «после задачи» | **НЕ РАБОТАЕТ** (конструкция, не дисциплина) | технически работает, но движок не доверяет модели: Stop-хук пишет кодом из фенс-блока ```memory``` в ответе |
| Механизм памяти | контуры 1–3 ниже | фенс-блок в output contract + Stop-хук мозга; handoff Гефесту (`/deploy-agent`) |

Один агент может жить в обоих рантаймах — тогда мозг проектируется на пересечении (оба контура, без относительных путей наружу).

## Трёхконтурная модель (рантайм = субагент CC)

### Контур 1 — нативное поле `memory:` (база, работает у всех из коробки)

Во frontmatter обёртки `.claude/agents/<name>.md` ставится `memory: project`. Официальный
механизм Claude Code (docs → Sub-agents → Enable persistent memory), проверен живым тестом
2026-07-20 (запись → recall из новой сессии):

- харнесс создаёт `.claude/agent-memory/<name>/` в корне проекта (скоуп `user` → `~/.claude/agent-memory/<name>/`, `local` → `.claude/agent-memory-local/`);
- в системный промпт субагента **автоматически** добавляются инструкции читать/писать память;
- первые **200 строк или 25KB** `MEMORY.md` инжектятся при каждом старте;
- Read/Write/Edit для памяти включаются автоматически.

`project` — рекомендованный дефолт (память шарится через git офиса). Ноль самодельной обвязки.

### Контур 2 — страховка: SubagentStop-хук → дистилляция (ОПЦИОНАЛЬНО — если hook-пак установлен)

Хук `capture-learnings.sh` на событии `SubagentStop` пишет `last_assistant_message` каждого
завершённого субагента в `<офис>/ops/agent-captures.jsonl` (append-only, flock). Скилл
`/distill-memory` по каденсу/размеру переносит достойное в `<офис>/agents/<name>/memory.md`
под approval. Пути зависят от топологии офиса (`office/` или `team/`). В свежем офисе без
хука этого контура нет — тогда контур 1 обязателен тем более: он единственный. Правило:
**где механизм записи вшит — там память живёт; без явного триггера/хука агент не пишет НИКОГДА.**

### Контур 3 — вход: память попадает в свежий контекст на старте

Чтение в НАЧАЛЕ контекста исполнимо (в отличие от записи в конце). Три канала:

1. нативный инжект `MEMORY.md` (контур 1 даёт бесплатно);
2. строка в теле обёртки: «прочитай `office/agents/<name>/memory.md`, grep `failures.md` по теме задачи»;
3. `SubagentStart`-хук с `additionalContext` (продвинутый вариант).

## Слои файлов агента — кто РЕАЛЬНО пишет

| Слой | Файл | Что хранит | Кто пишет |
|------|------|------------|-----------|
| Identity | `CLAUDE.md` / `core.md` | роль, процесс, характер | Демиург / template |
| Overrides | `overrides.md` | персональные правила клиента | Хозяин руками; `preserve_if_exists` при апдейте |
| Нативная память | `.claude/agent-memory/<name>/MEMORY.md` | выученные факты, паттерны | субагент в рантайме (харнесс инструктирует и инжектит) |
| Чистовик памяти | `memory.md` (append-only) | Decisions / Patterns / Context | `/distill-memory` из captures под approval; долгоживущая сессия — может сама |
| Failures | `failures.md` (append-only) | дата → предположил → оказалось → правило | тот же контур; grep перед задачей — обязанность агента |
| Knowledge | `knowledge/` | процедурная память — как делать | Демиург / Хозяин |

Тест при записи: «это инструкция на каждый раз или выученный факт?» Инструкция → core.md.
Факт → память. Append-only: факт изменился — новая запись с датой, старую не переписывать.

**Лимиты:** core ≤200 строк · `memory.md` ≤500 токенов · `MEMORY.md` — жёсткие 200 строк /
25KB (дальше харнесс не инжектит; при переполнении — консолидация: дубли слить, новое
побеждает с датой, устаревшее → архив).

## Lifecycle

**Перед задачей (исполнимо — это чтение):** grep `failures.md` по ключевым словам задачи →
прочитать `memory.md` / инжект MEMORY.md → если в брифе scout-досье, читать первым.

**После задачи:** попросить в промпте записать урок — МОЖНО (контур 1 это делает штатно),
но полагаться на это как на единственный механизм — ЗАПРЕЩЕНО. Гарантию даёт контур 2
(хук) либо нативный харнесс (контур 1).

**По каденсу (не «не забыть вызвать»):** `/distill-memory` — сырьё captures → чистовики;
консолидация memory.md при переполнении лимитов.

## Запрещено при сборке (чек Validator)

1. Прошивать «после задачи — append в memory.md» как единственный механизм памяти.
2. Оставлять обёртку субагента без поля `memory:` без осознанной причины.
3. Декоративные поля frontmatter (`mcp:`, `reports_to:`, `version:`) — Claude Code их игнорирует; официальные поля: `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `skills`, `mcpServers`, `hooks`, `memory`, `background`, `effort`, `isolation`, `color`.
4. «Затравочные записи» в failures.md как имитация живой памяти.
5. Протокол памяти долгоживущей персоны — агенту-субагенту (и наоборот): сначала Шаг 0.

## Справочное (не канон записи, а выбор хранилища — оставлено из прежней версии)

**Три горизонта:** working (context window) · short-term (state.json / Redis) · long-term
(markdown → vector при росте).

**Точка перехода к БД:** <100 файлов knowledge и <5 агентов → **Markdown + grep, точка**.
>100 файлов → pgvector / Mem0. Долгоживущие client-агенты с устаревающими фактами →
bi-temporal (Graphiti; можно начать markdown-frontmatter `valid_until`). Сессионное
ускорение → Redis. Не брать без причины: Pinecone (10-50× цена pgvector), Weaviate
(переусложнён), graph-only без vector.

**Чего НЕ хранить в памяти:** здоровье/диагнозы · госID · домашние адреса · пароли/токены ·
религия/политика · состояние текущей задачи (это TodoList) · код-паттерны (это код) ·
git history (это git log) · дубли memory-файлов.

**Эталоны:** официальные доки Claude Code → Sub-agents → Enable persistent memory
(первоисточник поля `memory:`) · Letta agent memory (3-слойная теория) · Zep/Graphiti
(bi-temporal) · Mem0 production paper. Формула «пишет промпт, страхует хук» — внутренний
канон, из которого выведен этот документ.
