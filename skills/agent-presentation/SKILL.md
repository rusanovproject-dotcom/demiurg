# /agent-presentation — онбординг-преза агента

## Назначение

Превращает любого агента офиса в HTML-презентацию для учеников или клиентов. Не «слайды о фичах», а нарратив: AI-слоп → разворот → знакомство с конкретным героем → методология → CTA. На выходе — деплоится на Vercel, открывается на вебинаре или отдаётся клиенту в личку.

## Эталон-кейс

Скилл вырос на реальном кейсе — презентации агента-копирайтера Логоса (18 слайдов, 3 круга правок). **Сами файлы того кейса в пак не входят** — это внутренний донор офиса-родителя. В пак вошло то, что от него ценно и переносимо:

- `references/pattern.md` — полный каркас презентации с одобренными текстами. **Это твой главный шаблон вместо файлов донора.**
- `references/examples-logos.md` — разбор кейса: какие круги правок были, что заворачивали и почему.
- `references/voice-tone.md` · `visual-system.md` · `interactivity-ideas.md` — голос, визуальная система, идеи интерактива.

Если у тебя есть свой донор (готовая преза, которая нравится) — положи путь к нему в brief, скилл прочитает его первым.

## Pipeline (8 фаз)

```
Phase 1 Discovery     → читаю агента, вытаскиваю фактуру
Phase 2 Имя+концепция → 6-8 вариантов, концепция в 1-2 предложениях
Phase 3 Скелет 17-18  → нарратив-каркас слайдов, тезисы
Phase 4 Voice & Tone  → текст слайдов с расщеплением «слоп vs живой»
Phase 5 Visual System → бренд, шрифты, glow, 3D-акценты
Phase 6 Portrait      → 4-8 концепций → выбор → Replicate
Phase 7 Build         → HTML/CSS/JS через Frontend-Designer субагента
Phase 8 Storage       → артефакт + все версии в <офис>/artifacts/
```

После каждой фазы — пауза, показываю Хозяину, ловлю фидбек. Не гоню до конца на первой попытке.

## Phase 1 — Discovery

Читаю файлы агента в `<офис>/office/agents/<agent>/` (или `office/agents/<agent>/`):

| Файл | Что вытащить |
|------|--------------|
| `core.md` (или `CLAUDE.md`) | методологии-классики, идентичность, фишка-отличие, формула работы |
| `knowledge/` | какие файлы читает перед задачей, есть ли voice/style/anti-patterns |
| `knowledge/voice-*.md` | надстили/регистры если есть (для слайда «N надстилей») |
| `skills/` | реальные скиллы — НЕ форматы (пост/лендинг = формат, voice-dna/stop-slop = скилл) |
| `memory.md`, `failures.md`, `overrides.md` | три тетради памяти — для слайда «динамическая память» |
| `soul.md` (если есть) | характер, как разговаривает, что не делает |

**Что записываю в карточку агента** (внутренний черновик, не показываю):
1. Главная роль (одна строка)
2. 2-3 главных скилла (имя команды + что делает в одно предложение)
3. Методологии классиков (Schwartz, Hormozi, Halbert — для копирайтера; Strauss, Sutherland — для маркетолога; и т.д.)
4. Регистры/надстили — если есть
5. Карта файлов (имя → 2-3 строки описания)
6. Фишка-отличие — чем этот агент непохож на других

Если фактуры мало (например, у агента нет надстилей) — слайды про это пропускаются. Не натягиваю шаблон на пустое.

## Phase 2 — Имя + концепция

Если агент уже с именем (Логос, Алекс, Гермес) — пропускаю. Если безымянный — предлагаю 6-8 вариантов **разной парадигмы**, не вариаций одной идеи:

- Античная (Логос, Аполлон, Плутос, Гермес, Афина)
- Литературная (Шекспир, Маяковский, Буковски, Бродский)
- Архетипическая (Архитектор, Скриб, Хамелеон, Алхимик)
- Технологическая (Нейрон, Кодекс, Атлас, Призма)
- Символическая (Камертон, Парадокс, Зеркало, Эхо)
- Народная (Иваныч, Добрыня)

К каждому имени — одна строка концепции. Концепция = «кто этот агент в твоём офисе» в 1-2 предложениях, без пафоса. Хозяин выбирает 1 → дальше работаю с этим.

## Phase 3 — Скелет 17-18 слайдов

Точная последовательность (нарушать только если у агента нет фактуры под слайд — тогда удалить, не натягивать):

| # | Слайд | Назначение |
|---|-------|-----------|
| 1-2 | AI-слоп самопрезентация | Гипертрофированный ChatGPT-голос. Ученик узнаёт знакомый дискомфорт |
| 3 | «Чувствуешь, что-то не то?» | Разворот. Большой H1 на пустом фоне |
| 4 | Причина | Почему AI пишет/делает плохо. 3 абзаца, последняя строка синим |
| 5 | Поворот | «Агент в твоей команде — из другой категории.» Одна фраза |
| 6 | Знакомство | Имя агента крупно + 2-3 строки представления + методологии классиков (синим) + финальная фраза-итог + 3D-портрет справа |
| 7 | 2 главных скилла | Два квадратика рядом. Над ними — 2 строки живого текста от агента |
| 8 | N надстилей/регистров (если есть) | Сетка 2×2 + один широкий. Над — 3 строки объяснения |
| 8.5 | «Запомни» (если есть надстили) | Одна фраза-удар. Минимум на экране |
| 8.6 | Корректировка стиля BEFORE/AFTER + speech-bubble (если есть надстили) | 3 блока: исходник → реплика → результат |
| 9 | Карта папок (интерактив) | Дерево файлов с hover-панелью справа + click → модалка |
| 9.5 | Динамическая память | Одна фраза-удар. Glow ярче |
| 10 | Память + притирка | 3 тетради (memory/failures/overrides) с описанием |
| 11 | Команда «запомни» | Как явно зафиксировать правило → overrides.md |
| 12 | Как со мной работать | Flow со стрелками: ТЫ → Я |
| 13 | 5 кнопок развилки | Маленькие квадратики 96×96 + пример конца текста выше |
| 14 | Под каждой кнопкой — отдельный скилл | Список скиллов с командами |
| 15 | Методология итеративной докрутки | «написал → докрутил → почистил → конфетка» |
| 16 | CTA | Одна команда крупно (моноширинный) + инструкция |

Если у агента нет надстилей — слайды 8/8.5/8.6 убираются. Если нет «развилки 5 кнопок» — слайды 13/14 заменяются на 1-2 слайда с реальной механикой.

## Phase 4 — Voice & Tone

**Главный закон:** два регистра на одной презе.

### Слайды 1-2 — AI-слоп нарочно

Гипертрофированно. Ученик должен УЗНАТЬ ChatGPT шкурой. Маркеры:
- Длинные тире через каждые 2 строки
- Тройки прилагательных («персонализированный, масштабируемый, бесшовный»)
- «Не X — а Y» в каждом абзаце
- «Давайте разберёмся», «инновационный», «парадигма», «синергия», «революционный», «трансформация», «на новый уровень»
- «На самом деле», «вот что важно понимать»
- Ложная агентность: «система анализирует», «алгоритм понимает»

Пример из кейса Логоса:
> «Это не просто инструмент — а ваш персональный AI-партнёр нового поколения, разработанный для трансформации того, как вы создаёте контент. На пересечении искусственного интеллекта и креативного мышления — он не просто пишет тексты. Он их чувствует.»

### Слайды 6+ — расслабленный «свой чувак»

От первого лица, как объяснил бы коллеге за кофе. Без эго, без манифестов. Мат — если уместен в стиле Хозяина, и только в кульминации (не в зачине). Ирония, юмор, самоирония.

**Запрещено в основном тексте:**
- Слова которые ученик не знает БЕЗ объяснения одной фразой: «регистр», «архитектура», «камертон», «layered memory» → заменяй на «надстиль», «как я устроен внутри», «твой голос»
- AI-слоп паттерны (всё что в слайдах 1-2)
- Бинарные «не X — а Y» в основном тексте — это AI-паттерн, спалится
- Корпоративные обороты: «таким образом», «в рамках данного»
- Восклицательные «Отлично!», «Замечательно!»

**Метафоры обязательны на технических слайдах.** «Три тетради» вместо «layered memory». «Камертон» если объясняешь одной фразой («то с чем сверяюсь перед каждой строкой»). «Карта папок» вместо «структура агента».

**Максимум 3 длинных тире на абзац.** Больше — AI-слоп даже в живом тексте.

**Финал — прогон через `/stop-slop`.** Обязательно для слайдов 6-16.

Полный гайд по голосу → `references/voice-tone.md`.

## Phase 5 — Visual System

### Палитра

| Hex | Где |
|-----|-----|
| `#070B17` | Фон brand-слайдов (НЕ `#000000` — на абсолютном чёрном glow не работает) |
| `#F5F5F5` | Фон слайдов 1-2 (AI-слоп) |
| `#1A6BFF` | Синий glow — главный акцент. Команды, имена методологов, имя агента, CTA |
| `#0F2060` | Глубокий синий — radial gradient в центре slide |
| `#FFFFFF` | Основной текст |
| `#6B7280` | Второстепенный текст (italic, подписи) |
| `#111827` | Подложки карточек |
| `#1E2A45` | Border карточек |

### Шрифты

- **Space Grotesk** — заголовки, тело на brand-слайдах (700 для H1, 600 для H2, 400 для body)
- **Inter** — слайды 1-2 (AI-слоп). Это «корпоративный нейтральный», узнаётся бессознательно как ChatGPT/Notion
- **JetBrains Mono** — команды, имена файлов, code-блоки

### Стиль

- **Монолит** для технических слайдов — минимализм, пространство, один синий акцент
- **Аполлон-пик** один раз на слайде знакомства — 3D-портрет справа, 35-40% ширины
- Glow точечный: только на именах команд, имени агента, CTA (`text-shadow: 0 0 32px rgba(26,107,255,0.5)`)
- Glow-луч на фоне brand-слайдов: горизонтальная линия в центре + radial ellipse
- Иконки — НЕ использовать. Никаких feather/emoji/fluent — делают шаблон. Стрелки символьные (→ ▼ ─)

### Слайды 1-2 — иронично-идеальная корпоративная вёрстка

Ирония в ТЕКСТЕ, не в кривой вёрстке. Inter, светлый фон, аккуратные bullet через тире, лёгкая тень на контейнере, горизонтальная линия снизу. Должно выглядеть как Notion-шаблон.

### Переход 2→3

Cut с чёрной вспышкой 80ms. НЕ fade. Резкий разрыв = осознанный приём.

Полная дизайн-система → `references/visual-system.md`.

## Phase 6 — Portrait generation

1. **Designer-субагент готовит 4-8 концепций** разной парадигмы (НЕ вариации одной идеи). Например для Логоса было: Оракул, Уличный поэт, Scribe-киборг, Shadow-data. Каждая концепция — отдельный персонаж с другим архетипом.
2. **Хозяин смотрит — выбирает 1-2.** Если не зашло — вторая итерация (для Логоса второй раунд был «греческий киберпанк»: Живой мрамор, Нейрограф, Пифия 2099, Аполлон-Сингулярность).
3. **Промт для генерации** — ≤2000 символов, aspect ratio 3:4, поясной портрет, фон `#080A0F`, синий glow `#1A6BFF`.
4. **Replicate `nano-banana-pro`** — стабильнее `nano-banana-2` на длинных промтах, не падает в timeout. Использовать `nano-banana-pro` по умолчанию.
5. **Отправка в Telegram через Bot API + curl.** НЕ через MCP (MCP-telegram нестабилен).
6. **Хранение:** все портреты — в `<artifact-folder>/<agent-name>/01-concept.png`, `02-...`, и т.д.

## Phase 7 — Build & Deploy

1. **HTML one-page**, чистый CSS + vanilla JS. БЕЗ Tailwind, БЕЗ Framer Motion — overkill для одной презы.
2. **Frontend-Designer субагент** собирает по `copy-v*.md` (последняя версия) + `visual-plan-v*.md` (последняя версия). На входе — оба файла, на выходе — `index.html`.
3. **Интерактив:**
   - **Hover на файлы карты папок** → sticky-панель справа с описанием 250-400 символов. Описание объясняет КАК файл работает, ЧТО в нём, КОГДА читается агентом — НЕ повтор того что слева
   - **Click на файл** → модалка с full-описанием (400-600 символов)
   - 5 кнопок развилки — hover расширяет border до синего + glow
4. **Деплой:** `vercel --prod` из папки артефакта. В `vercel.json` — `{"cleanUrls": true}` если нужно.

## Антипаттерны (Хозяин их заворачивал)

1. **Слишком много текста на слайде.** Плотные абзацы — ученик не читает. Ударные слайды (3, 5, 9.5, 8.5) — 1-2 строки. Концептуальные — 5-7 строк.
2. **Воду / вступления / самосообщения** — режь беспощадно.
3. **Описания «по факту повтор того что слева»** — описания должны быть СУЩНОСТНО подробнее. Если в дереве папок написано «voice.md ← твой голос», в hover-панели НЕ пиши «это файл с голосом» — объясни как создаётся, когда читается, что внутри.
4. **Бинарные «не X — а Y» в основном тексте** — это AI-паттерн, спалится. Используй только в слайдах 1-2 (там нарочно).
5. **Слова «регистр», «архитектура», «камертон»** без объяснения — никто не знает что это. Используй «надстиль», «как я устроен внутри», «то с чем сверяюсь».
6. **Запоминай что Хозяин назвал AI-слопом** — записывай в `failures.md` агента и не повторяй.
7. **Не показывай форматы как методологии.** Посты/лендинги/лонгриды — это форматы. Schwartz/Halbert/Sugarman — это методологии. На слайде знакомства — только методологии.

## Routing — кто во что играет

| Роль | Кто | Что делает |
|------|-----|-----------|
| Trigger / Triage | **Director** | Видит запросы «сделай презу про агента / упакуй агента / онбординг / вебинар про агента» в `routing-patterns.md` → запускает скилл |
| Owner / Оркестратор | **Demiurg** (Архитектор) | Ведёт все 8 фаз. Знает скилл из `demiurg/CLAUDE.md`. Делегирует Phase 4/6/7 |
| Phase 4 (Voice) | **Copywriter** субагент | Пишет тексты слайдов 6-16 в голосе агента + финальный `/stop-slop` |
| Phase 6 (Portrait) | **Designer** субагент | 4-8 концепций персонажа + Replicate-промты. Бренд = бренд агента (не Arctic Cold Light по умолчанию) |
| Phase 7 (Build) | **Frontend-Designer** субагент | HTML/CSS/JS one-page по `copy-v*.md` + `visual-plan-v*.md` |
| Optional consult | **Methodologist** | Если ученики курса — даёт обратную связь по нарративу обучения (Bloom's, Quick Win) |
| QA review | `agent-quality-reviewer` (скилл) | Можно прогнать готовый SKILL/преза на рубрику качества |

## Decision points (где Хозяин решает)

- **Имя агента** — после Phase 2 (выбирает из 6-8 вариантов)

- **Финальный текст слайдов** — после Phase 4 v1 (часто будет v2/v3)
- **Деплой** — после Phase 7 (проверяет HTML локально, потом разрешает `vercel --prod`)
