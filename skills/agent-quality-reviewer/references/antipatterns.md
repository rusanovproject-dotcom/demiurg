# Каталог антипаттернов AI-агентов

> Источники: Reddit r/ClaudeAI, r/AI_Agents, HackerNews, Habr, Simon Willison, Karpathy, Latent Space
> Обновлено: март 2026

## Категория 1: АРХИТЕКТУРНЫЕ АНТИПАТТЕРНЫ

### AP-01: "Суперагент" (God Agent)

**Описание:** Один агент пытается делать всё — код, тесты, контент, деплой, аналитику.

**Почему плохо:**
- Контекст раздувается, качество падает
- Невозможно отладить — непонятно что сломалось
- Нельзя масштабировать — один агент = одно узкое место

**Как исправить:**
Разбей на 3-5 специализированных агентов. Каждый с узкой ролью.

```
ПЛОХО:
  Universal Agent → делает всё

ХОРОШО:
  Researcher → только исследует
  Coder → только пишет код
  Reviewer → только проверяет
  Deployer → только деплоит
```

**Правило (Anthropic C compiler case):** 2 команды по 4 узких агента > 1 команда из 8 широких.

---

### AP-02: "Бесконечный цикл" (Infinite Loop)

**Описание:** Агент застревает в цикле retry без ограничения.

**Почему плохо:**
- Съедает токены (до $500+ на одном failed run)
- Блокирует pipeline
- Может зависнуть навсегда

**Как исправить:**
```
max_iterations: 3
on_max_reached: escalate_to_human
timeout_per_iteration: 20_minutes
```

---

### AP-03: "Телефонный перевод" (Lost in Translation)

**Описание:** Агенты передают друг другу только результат, но не контекст решений.

**Почему плохо:**
- Следующий агент не понимает ПОЧЕМУ было принято решение
- При ошибке непонятно куда откатываться
- Переделка с нуля вместо точечного фикса

**Как исправить:**
Передавай не только output, но и decision_context:
```json
{
  "result": "выбрана архитектура X",
  "decision_context": {
    "alternatives_considered": ["Y", "Z"],
    "why_chosen": "X лучше масштабируется",
    "trade_offs": "сложнее в настройке"
  }
}
```

---

### AP-04: "Токеновый пожар" (Token Burn)

**Описание:** Мультиагентная система тратит 15x токенов без контроля.

**Данные (Simon Willison):**
- Chat: 1x токенов
- Single agent: ~4x токенов
- Multi-agent: ~15x токенов

**Как исправить:**
- Кэшируй результаты между агентами
- Используй async вместо sync
- Мониторь cost per task
- Budget alerts: "если задача > $5, стоп и спроси"

## Категория 2: АНТИПАТТЕРНЫ РОЛЕЙ

### AP-05: "Размытая роль" (Vague Identity)

**Описание:** "Ты — полезный AI-ассистент" вместо конкретной роли.

**Как исправить:**
```markdown
ПЛОХО:
  Ты — AI-помощник. Помогай пользователю.

ХОРОШО:
  Ты — Senior FastAPI Engineer с 8 годами опыта.
  Специализация: REST API, PostgreSQL, Docker.
  Ты НЕ делаешь: фронтенд, дизайн, контент.
  При запросе вне своей зоны → направляй к соответствующему агенту.
```

---

### AP-06: "Пересекающиеся зоны" (Overlapping Roles)

**Описание:** Два агента делают одно и то же, конфликтуют.

**Как исправить:**
- Явно определи зону каждого агента
- Используй "ownership matrix" — кто за что отвечает
- При конфликте — один уступает по определённому правилу

---

### AP-07: "Роль без примеров" (Role Without Examples)

**Описание:** Роль описана словами, но нет примеров хорошей/плохой работы.

**Почему плохо:**
- Claude понимает decision rules лучше, чем теорию
- Без примеров агент интерпретирует инструкции по-своему

**Как исправить:**
К каждой ключевой инструкции добавь:
```markdown
ПРИМЕР (хорошо): [конкретный пример]
ПРИМЕР (плохо): [что НЕ делать]
```

## Категория 3: АНТИПАТТЕРНЫ КОНТЕКСТА

### AP-08: "Перегруженный CLAUDE.md" (Context Overload)

**Описание:** CLAUDE.md на 1000+ строк с всей информацией сразу.

**Почему плохо:**
- Агент теряет фокус в длинном контексте
- Важные инструкции "тонут" среди неважных
- Тратятся токены на загрузку ненужного

**Как исправить:**
- CLAUDE.md: max 200 строк — только ядро
- Детали: в отдельных файлах, загружать по запросу
- Progressive disclosure: metadata → core → references

---

### AP-09: "Мёртвый контекст" (Stale Context)

**Описание:** state.md не обновляется, агент работает с устаревшей информацией.

**Как исправить:**
- После каждой задачи → обнови state.md
- Добавь дату последнего обновления
- Периодический аудит: "этот файл актуален?"

---

### AP-10: "Контекст без источника правды" (No Source of Truth)

**Описание:** Агент "помнит" но нигде не записано. Между сессиями — теряется.

**Как исправить:**
- Определи source of truth для каждого типа информации
- State: state.md | Решения: decisions/ | Архитектура: architecture.md
- "Агент работает с внешней точкой правды, а не с тем что помнит"

---

## Категория 4: АНТИПАТТЕРНЫ БЕЗОПАСНОСТИ

### AP-11: "Lethal Trifecta" (Simon Willison)

**Описание:** Агент имеет доступ к private data + untrusted content + exfiltration tools.

**Как исправить:**
Никогда не давай агенту все три одновременно:
- Private data (БД, секреты, персональные данные)
- Untrusted content (пользовательский ввод, веб-скрейпинг)
- Exfiltration (email, API calls, file upload)

Изолируй: один агент читает, другой пишет, ревьюер проверяет.

---

### AP-12: "Автономия без надзора" (Unsupervised Autonomy)

**Описание:** Агент деплоит, удаляет, тратит деньги без подтверждения.

**Karpathy:** "99% automation + 1% human review > 100% automation"

**Как исправить:**
```
Критичные действия (ВСЕГДА human approval):
- Deploy to production
- Delete data/files
- Spend money > $20
- External communications
- Changes to infrastructure
```

---

### AP-13: "Секреты в контексте" (Secrets in Context)

**Описание:** API ключи, токены, пароли в CLAUDE.md или промптах.

**Как исправить:**
- Секреты только в .env
- Агент не видит ключи — вызывает tool который их использует
- Никогда не логировать секреты

## Категория 5: АНТИПАТТЕРНЫ КОМАНД

### AP-14: "Слишком много агентов" (Agent Explosion)

**Описание:** 10+ агентов без координации.

**Реальность:** 10 агентов = экспоненциальная координация. Начни с 3-4.

**Правило:**
- 1-3 агента: простая координация
- 4-6: нужен orchestrator
- 7-10: нужна иерархия (supervisor → team leads)
- 10+: скорее всего ты делаешь что-то не так

---

### AP-15: "Нет мониторинга" (Flying Blind)

**Описание:** Агенты работают, но не видно что происходит.

**Из Reddit:** "Without monitoring, we spent $500+ on failed runs"

**Минимальный мониторинг:**
- Tokens per agent per task
- Time per task
- Error rate
- Cost per task
- Task completion rate

---

### AP-16: "Копипаста архитектуры" (Cargo Cult Architecture)

**Описание:** Скопировал архитектуру из туториала без понимания зачем.

**Как исправить:**
Задай себе вопросы:
1. Почему именно этот паттерн?
2. Что случится если убрать этого агента?
3. Какая задача оправдывает мультиагент (>4 часов для человека)?
4. Какой ROI от этой архитектуры?
