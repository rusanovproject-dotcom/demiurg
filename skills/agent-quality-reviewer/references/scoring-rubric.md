# Scoring Rubric — Детальная рубрика оценки

## Как использовать

Каждое из 8 измерений оценивается по шкале. Ниже — конкретные примеры
для каждого балла, чтобы оценка была объективной и воспроизводимой.

---

## 1. Роль и идентичность (0-15)

| Балл | Описание | Пример |
|------|----------|--------|
| 15 | Узкая роль + backstory + границы + примеры поведения | "Senior FastAPI Engineer (8 лет). Специализация: REST API, PostgreSQL. НЕ делает: фронтенд, дизайн. При запросе вне зоны → направляет к Head of Content." |
| 12 | Роль конкретная, но без примеров или границ | "Ты — Backend Developer. Пишешь код на Python." |
| 8 | Роль есть, но широковата | "Ты — разработчик. Помогаешь с кодом и тестами." |
| 5 | Роль формальная, по факту делает всё | "Ты — CTO. Делаешь код, контент, стратегию, деплой." |
| 2 | "Ты — AI помощник" | Generic identity без специализации |
| 0 | Нет роли вообще | Просто промпт без определения кто это |

---

## 2. Контекст и память (0-15)

| Балл | Описание | Признаки |
|------|----------|----------|
| 15 | Полная система контекста | Context pack при старте, source of truth, shared memory, обновление после задач, decision log |
| 12 | Хороший контекст | Есть state.md, context loading, но нет decision log или обновление нерегулярное |
| 8 | Базовый контекст | CLAUDE.md с инструкциями, но нет state management |
| 5 | Минимальный | Только CLAUDE.md, нет динамического контекста |
| 2 | Почти нет | Пара строк инструкций |
| 0 | Пусто | Нет контекстной системы |

**Автоматическая проверка:**
- [ ] Есть файл state.md или context.md?
- [ ] Есть инструкция "загрузи контекст при старте"?
- [ ] Есть инструкция "обнови после задачи"?
- [ ] Есть decision log / history?
- [ ] Контекст < 500 строк (не перегружен)?

---

## 3. Инструменты (0-10)

| Балл | Описание | Признаки |
|------|----------|----------|
| 10 | 3-5 инструментов, точно под задачу | GitHub MCP + Filesystem для кодера. Brave Search + Playwright для ресёрчера. Least privilege. |
| 8 | Инструменты есть, в целом подходят | 4-6 инструментов, но 1-2 лишних |
| 5 | Не оптимально | Слишком много (>8) или слишком мало (1) |
| 3 | Проблемы | Инструменты не соответствуют задаче или нет ограничений доступа |
| 0 | Нет инструментов | Агент = текстовый генератор |

---

## 4. Guardrails (0-15)

| Балл | Описание | Что есть |
|------|----------|----------|
| 15 | Полный набор | Iteration limits, bounded delegation, error handling, human-in-the-loop, timeout, запреты на опасные действия, escalation protocol |
| 12 | Хорошие guardrails | Есть human-in-the-loop и error handling, но нет timeouts или iteration limits |
| 8 | Базовые | "Спроси перед деплоем", "не удаляй без подтверждения" |
| 5 | Минимальные | "Будь осторожен" без конкретики |
| 2 | Формальные | Одна строка про безопасность |
| 0 | Отсутствуют | Агент может делать что угодно |

**Критичные проверки (каждая = -3 балла если отсутствует):**
- [ ] Human approval для deploy?
- [ ] Human approval для delete?
- [ ] Запрет на секреты в контексте?
- [ ] Error recovery protocol?
- [ ] Max iterations limit?

## 5. Task Specification (0-10)

| Балл | Описание | Признаки |
|------|----------|----------|
| 10 | Полная спецификация | Декомпозиция задач, input/output contracts, DoD, structured formats (JSON/YAML) |
| 8 | Хорошая | Есть декомпозиция и DoD, но не формализована |
| 5 | Средняя | Задачи описаны текстом, нет контрактов |
| 3 | Слабая | "Сделай фичу" без деталей |
| 0 | Нет | Нет процесса спецификации задач |

---

## 6. Координация (0-15)

| Балл | Для одиночного агента | Для команды |
|------|----------------------|-------------|
| 15 | Чётко вписан в команду, знает кому передать | Communication protocol, правильный паттерн, state management |
| 12 | Знает про других агентов | Координация есть, не полностью формализована |
| 8 | Может передать задачу | Агенты как-то общаются через файлы |
| 5 | Не знает про команду | Ad-hoc коммуникация |
| 0 | Изолирован | Нет координации |

---

## 7. Observability (0-10)

| Балл | Описание | Что есть |
|------|----------|----------|
| 10 | Полная | Логи + метрики + traces + дашборд + алерты |
| 8 | Хорошая | Логи + метрики, можно отследить проблемы |
| 5 | Базовая | Есть лог-файл |
| 3 | Минимальная | Вывод в консоль |
| 0 | Нет | "Работает и ладно" |

---

## 8. Масштабируемость (0-10)

| Балл | Описание | Признаки |
|------|----------|----------|
| 10 | Модульный | Легко добавить инструменты, версионирование, документация, feedback loop |
| 8 | Расширяемый | Можно добавить, но нужны усилия |
| 5 | Средний | Некоторые части модульные, некоторые — нет |
| 3 | Монолитный | Тяжело менять, всё в одном файле |
| 0 | Одноразовый | Не масштабируется |

---

## Итоговые уровни

| Диапазон | Уровень | Рекомендация |
|----------|---------|--------------|
| 85-100 | ELITE | Production-ready. Поддерживай и оптимизируй. |
| 70-84 | STRONG | Хорошая база. 2-3 улучшения сделают ELITE. |
| 50-69 | DEVELOPING | Работает, но много пробелов. Фокус на P0. |
| 30-49 | WEAK | Серьёзная переработка нужна. Начни с guardrails и роли. |
| 0-29 | CRITICAL | Лучше переписать с нуля, используя best-practices.md. |
