# TRAIN — обучение агента на корпусе материалов (embed-into-agent)

Когда читать: активирован режим TRAIN алхимика (вшивка корпуса книг/тренингов/транскриптов
в базу знаний конкретного агента). Это полная методология режима; в SKILL.md — только конвейер.

Источник канона: индустрийный ресёрч 2025-26
(Anthropic context engineering, Karpathy LLM Wiki, book-to-skill, Manus, Contextual Retrieval)
+ адверсарное ревью концепта 2026-07-21.

---

## Ниша (что это и что это НЕ)

**Это:** корпус обучающих материалов (книги, тренинги, курсы, транскрипты) → дистиллированная
методология + база знаний КОНКРЕТНОГО агента, встроенная в его роутинг. Автор материалов ≠
владелец агента: учим агента на чужих знаниях.

**Это НЕ** (если в твоём офисе есть отдельные агенты под эти зоны — роуть туда; иначе
режим самодостаточен и делает всё сам):
- разовый один материал «прочитай и учти» — тут корпус-конвейер избыточен, проще внедрить вручную
- мозг-двойник ЧЕЛОВЕКА с его identity/голосом (корпус эксперта-владельца) — это другой жанр,
  TRAIN вшивает ПРЕДМЕТНУЮ методологию в рабочего агента, без личности и голоса
- просто сложить факты в общую базу знаний без привязки к конкретному агенту
- выбор архитектуры хранилища (vector DB, RAG) — здесь дефолт файлы+INDEX+grep, см. принцип 2

## 10 принципов ядра (консенсус индустрии 2025-26 — не нарушать)

1. **Контекст — конечный ресурс, не свалка.** Минимальный набор high-signal токенов; «влить
   книгу в контекст» запрещено — качество моделей деградирует задолго до лимита окна
   (context rot, Chroma).
2. **Файлы + INDEX + grep, не векторный RAG.** Anthropic убрала вектора из Claude Code,
   за ней Cursor/Windsurf/Devin. Порог: база до ~10 000 файлов-атомов — файлы; стабильные
   промахи recall выше порога → эскалация на vector-слой.
3. **Progressive disclosure — 3 уровня.** INDEX.md (discovery: что где лежит) → атомы
   (activation: lazy-load по триггеру) → цитаты ЗАПЕЧЕНЫ в атомах. Агент в рантайме
   НЕ читает raw-книги — это context rot.
4. **Дистилляция ≠ суммаризация.** Из материала вытаскиваются ИМЕНОВАННЫЕ фреймворки,
   правила решений, антипаттерны — не пересказ. Плотность важнее полноты: фреймворк на
   1K токенов бьёт выдержку на 10K.
5. **Атом обогащён и самодостаточен.** Каждый атом несёт строку-контекст («Из книги X,
   гл. 3 — про Y») и цитату-якорь — grep-хит понятен без чтения соседей
   (Contextual Retrieval: −49% ошибок ретрива).
6. **Знание компаундится.** [[связи]] между атомами обязательны (атом без Related = сирота);
   INDEX обновляется каждым ингестом; changelog фиксирует что и когда вшито.
7. **Distill-then-verify.** Дистилляция без проверки против оригинала тихо теряет знания.
   Golden-set создаётся ДО дистилляции, проверка — ПОСЛЕ вшивки.
8. **КАК отдельно от ЧТО.** Методология (как работать) → `knowledge/methodology/CORE.md`,
   факты → `knowledge/domain/`. В SKILL.md агента — только handle-ссылки, НЕ inline
   (inline 15 фреймворков = 300 строк всегда в контексте — ломает progressive disclosure).
9. **Raw не едет в агента.** Полные тексты книг — build-time staging ВНЕ папки агента
   (объём + копирайт). В агента едут только атомы с цитатами-якорями.
10. **Один факт = одно место.** Дедуп внутри корпуса и против уже вшитого knowledge/;
    повтор у нескольких авторов = вес ядра (frequency++), не копия.

## Два профиля исполнения

| | **lite** (дефолт) | **full** (расширенный офис) |
|---|---|---|
| Ingestion видео | просит готовый транскрипт (авто-сабы YouTube, вставить текстом) | своя транскрибация (Whisper/Deepgram) |
| PDF/EPUB/DOCX | markitdown (`pip install markitdown`), preflight с человеческой ошибкой | + docling для тяжёлых PDF |
| Большой корпус | ТОЛЬКО последовательно: источник → чекпоинт → следующий | можно рой субагентов (top-level оркестрация) |
| VERIFY | лёгкий: 5-8 вопросов по сэмплу, один прогон, без авто-цикла | строгий: 20-30 + hard negatives, recall ядра ≥90%, макс 2 раунда |
| Зоны-соседи | нет — режим самодостаточен | если есть отдельные агенты внедрения/памяти — роуть по ним |

Preflight (такт CONVERT): проверь тулы ДО старта (`python3 -c "import markitdown"` и т.п.).
Нет тула → скажи по-русски что поставить или предложи обходной путь (вставить текст руками).
Не вываливай стектрейс.

## Пайплайн — 8 тактов

### Такт 1 — INTAKE (два входа)
- **Из конвейера /build (фаза KNOWLEDGE):** job-definition агента уже есть в брифе —
  НЕ переспрашивай роль. Прими хэндоффом: роль, задачи, материалы.
- **Standalone («обучи моего агента на этих материалах»):** спроси одним сообщением:
  1. Какой агент и какая у него РАБОТА (Action Mapping: что должен ДЕЛАТЬ →
     что для этого знать → минимум теории; НЕ «покрыть весь текст»)
  2. Материалы: что, форматы, примерный объём
  3. Авторы: один или несколько; при противоречии чьё слово решает (веса)
  4. Агент новый или живой (brownfield — см. такт 6)

### Такт 2 — CONVERT
- Preflight тулов (см. профили). Всё → markdown в staging: `_train-staging/{agent}/raw/`
  (ВНЕ папки агента; в пак/репо агента не едет).
- Raw immutable: руками не редактируется, дальше только читается.
- Каждому файлу — `content_hash` (первые 12 hex sha256) в манифест
  `_train-staging/{agent}/manifest.json` — основа идемпотентности и доливок.

### Такт 3 — MAP
- Карта корпуса: источники, структура (главы/уроки), объём в токенах (~символы/4).
- Режим прохода: источник ≤100K символов → один проход; больше → чанк по главам
  (structure-aware; semantic-разрез только для кусков сверх лимита).
- Корпус >500K токенов суммарно: СТРОГО последовательно — источник → DISTILL →
  чекпоинт в манифест (`status: distilled`) → при выгорании контекста /clear →
  resume по манифесту. Рой субагентов — только профиль full (top-level оркестрация), не дефолт.
- Создай golden-set ЗАРАНЕЕ по сэмплу raw (см. такт 7) — пока корпус ещё «свежий глаз».

### Такт 4 — DISTILL (по источнику)
Работают Стадии 2-4 алхимика (EXTRACT 8 категорий → STRUCTURE 4 слоя → ATOMIZE)
+ надстройка TRAIN:
- Фильтр Action Mapping: извлекаем то, что нужно агенту ПОД ЕГО РАБОТУ. Остальное —
  строкой в coverage-отчёт («в источнике есть тема Z — не взята: вне работы агента»).
- Каждый атом — по формату ниже: именованный фреймворк + «когда применять» + антипаттерн
  + цитата-якорь + строка-контекст.
- Счётчик покрытия по категориям (как Стадия 6 алхимика) — пишется в манифест.

### Такт 5 — MERGE (кросс-источники)
- Точный смысловой дубль → схлоп в один атом, `frequency++` (частота у разных авторов =
  вес принципа в ядре). Jaccard-мёрж «похожих» ЗАПРЕЩЁН — похожие ≠ одинаковые.
- Противоречие источников → резолв НА БИЛДЕ по весам авторов из INTAKE: победитель =
  основной текст атома, проигравший = секция «Альтернативный взгляд (Автор B): ...»
  в том же атоме. Веса не решают → вопрос Хозяину списком, не молча.
  Отдельных конфликт-файлов в рантайм не оставляем (context clash).
- Доливка (инкремент): дедуп новой пачки И против уже вшитого `{agent}/knowledge/` —
  по content_hash источников и по смыслу атомов.

### Такт 6 — WEAVE (вшивка в агента)
Структура в агенте:
```
{agent}/knowledge/
  INDEX.md                    ← триггер-карта: path + triggers + when (L1, всегда)
  methodology/
    CORE.md                   ← ядро: ~7-15 принципов (эвристика, не закон) + ссылки на фреймворки
    frameworks/<name>.md      ← фреймворки целиком (1 файл = 1 фреймворк)
  domain/<тема>/<atom>.md     ← атомы фактов/техник (1 файл = 1 атом, [[связи]])
  _eval/golden-set.md         ← вопросы приёмки (регрессия при доливках)
  _review/                    ← низкая уверенность — карантин до апрува
  changelog.md                ← что/когда вшито, из каких источников
```
- В INDEX.md на каждый файл: `triggers: [ключи]` + `when: <когда загружать>`.
- SKILL.md рабочего скилла агента и CLAUDE.md — только handle-ссылки
  («перед задачей X прочитай methodology/CORE.md»), НИКАКИХ inline-копий.
- **Brownfield-протокол (живой агент) — обязателен:**
  1. Бэкап текущего knowledge/ агента → `_archive/<YYYY-MM-DD>-pre-train/`
  2. Конфликт-чек новых атомов против СУЩЕСТВУЮЩЕГО knowledge/ (противоречия → списком Хозяину)
  3. Approval Хозяина на манифест вшивки (что добавится/изменится) ДО записи
  4. После вшивки — `validate-agent.sh {agent}` (офис) / smoke-вопрос агенту (пак)

### Такт 7 — VERIFY (distill-then-verify)
- Golden-set создан в такте 3 ПО RAW (не по атомам — иначе генератор проверяет сам себя).
- Вопросы целят в ЯДРО (фреймворки, которые агент будет применять в работе), не в каждый
  факт: «плотность > полноты» и «recall каждого факта ≥90%» — противоречат друг другу.
  Меряем recall ядра.
- Профиль pack: 5-8 вопросов, один прогон агента (или чтение его базы), LLM-судья.
  Провал → точечно дораспаковать промахнувшиеся места. Без автоцикла.
- Профиль office: 20-30 вопросов + hard negatives («чего в корпусе НЕТ» — агент не должен
  выдумывать), recall ядра ≥90%, при провале возврат на DISTILL, максимум 2 раунда,
  дальше эскалация Хозяину.
- Golden-set остаётся в `_eval/` — прогонять при каждой доливке (регрессия).

### Такт 8 — REPORT
```
TRAIN REPORT
════════════
Агент: {name} | Корпус: N источников, ~N токенов
Вшито: N атомов (domain) + CORE.md (N принципов) + N фреймворков
Coverage: {по категориям, % } | Не взято (вне работы агента): {список тем}
Конфликты: N резолвлено весами, N ждут Хозяина
VERIFY: {профиль} — {N/N вопросов, recall ядра X%}
_review/: N атомов ждут апрува
Доливка: кинь новые материалы → такты 2-7 инкрементально (манифест помнит хэши)
```

## Формат атома (шаблон)

```markdown
---
id: <kebab-slug>
source: «Название» — Автор, гл. 3 (или урок 2, таймкод 14:20)
confidence: high | medium | low
frequency: 1        # ↑ при схлопе дублей из разных источников
---
# <Именованное название фреймворка/принципа>

Контекст: из «Название» (Автор), гл. 3 — про <о чём>.

Суть: <2-6 строк, голосом практика: «делай X когда Y»>

Когда применять: IF <ситуация> THEN <действие>. НЕ применять когда <границы>.

Антипаттерн: <имя ошибки + триггер, по которому её узнать>

Цитата-якорь: «<дословная ключевая цитата>» (гл. 3 / таймкод)

Related: [[atom-2]], [[atom-7]]
```

Правила: 1 файл = 1 атом; атом ≤60 строк; confidence: low → файл идёт в `_review/`,
не в domain/; атом без Related — сирота, найди связь или объединяй.

## Пороги и лимиты (сводка)

| Что | Порог | Действие при превышении |
|---|---|---|
| Источник за один проход | ≤100K символов | чанк по главам + чекпоинты |
| Корпус целиком | >500K токенов | только последовательный режим с манифестом |
| База агента | ~10K атомов | эскалация на vector-слой (или отдельный агент памяти, если есть) |
| CORE.md | ≤200 строк | лишнее → frameworks/ |
| INDEX.md | ≤150 строк | дели domain/ на подтемы со своими INDEX |
| Атом | ≤60 строк | это конспект, а не атом — дели |
