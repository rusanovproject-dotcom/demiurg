# Demiurg — архитектор AI-систем

Демиург собирает AI-агентов и AI-офисы как **системы вокруг знаний**, а не клоны шаблонов. Один скилл, два режима, конвейер фаз (схема ниже), своя память.

```
INTAKE → BRIEF → SCOUT → ADOPT → KNOWLEDGE → BUILD → VALIDATE → ITERATE → WIRE (→ DEPLOY-HANDOFF, если ТГ)
```

---

│   ├── offer-principles.md

    ├── validate-office.sh  # проверка офиса целиком

### Скиллы

| Скилл | Что делает | Когда звать |
|-------|-----------|-------------|
| `build` | Единый скилл сборки, режимы SINGLE / TEAM / TRAIN — канон конвейера | Создать агента, скилл или целый офис |
| `scout` | Разведка домена перед сборкой: люди, методологии, готовые скиллы, MCP | Перед сборкой в незнакомой теме |
| `knowledge-alchemist` | Сырой контент (транскрипт, книга, курс) → готовый агент со вшитой методологией | Есть материал, из которого нужен специалист |
| `knowledge-extractor` | Сырой контент → структурированная база знаний офиса (без сборки агента) | Нужны знания, не агент |
| `adapt-employee` | Готовый агент → адаптирован под другой офис (голос, проводка, чистка чужих данных) | Переносишь агента себе или клиенту |
| `agent-quality-reviewer` | Ревью качества агента по 8 измерениям, оценка 0-100 + pre-publish гейт комплектности | Перед запуском агента и **обязательно** перед публикацией пака |
| `agent-presentation` | Онбординг-презентация агента: HTML, 17-18 слайдов с интерактивом | Показать агента ученикам или клиенту |

Аудит офиса целиком — не зона Демиурга, это отдельный агент-хранитель (`/office-cleaner`), снят отсюда 21.07.2026.

## Как пользоваться

### Один агент или скилл — режим SINGLE (10-30 мин)

Триггеры: `создай агента`, `один скилл`, `добавь агента`.

`INTAKE → BRIEF → SCOUT → ADOPT → KNOWLEDGE → BUILD → VALIDATE → ITERATE → WIRE (→ DEPLOY-HANDOFF, если ТГ)` —
единственное каноническое описание фаз и гейтов: `skills/build/SKILL.md`.

### Целая команда — режим TEAM (45-90 мин)

Триггеры: `собери команду`, `wizard`, `офис с нуля`.

Wizard ведёт через intake → blueprint → состав команды → для каждого агента: scout → adopt → knowledge → build → validate (eval) → iterate → финальный wire + soul + onboarding.

## Принципы

1. **Агент строится ВОКРУГ знаний.** Без data-pack — пустышка с правильной структурой.
2. **Few-shot побеждает abstract guidelines.** В `knowledge/examples/` — реальные образцы, Builder их читает.
3. **Score < 5 = блокер.** Программный, в `_score.json`. Текстовый блокер модель игнорирует.
4. **Self-trigger rules — хардкоды.** Если условие выполнено — действие обязательно. Без интерпретации.
5. **Validator + validate-agent.sh.** Бесплатная проверка ловит 80% проблем без LLM.
6. **Память Демиурга — корневые `memory.md`/`failures.md`; собранным агентам — поле `memory:` в обёртке + страховочный хук** (канон `knowledge/architecture/memory-architecture.md`).

## Заглушки и плейсхолдеры

В `knowledge/examples/` — образцы агентов с абстрактными именами проектов (`my-app`, `my-project`, `my-bot`). Не копируй пути дословно — это шаблон структуры, не готовый агент.

`memory.md`/`failures.md` — заполняются по ходу работы (append-only).

## Конвейер качества

```
Demiurg (создаёт) → validate-agent.sh → Validator → поведенческий eval (1-3)
                                                          │
                                                          ▼
                                              боевая приёмка (4-6)
                                                          │
                                                          ▼
                                          (опционально) внешний review → polish
```

Внешние ревьюер и полировщик не входят в репо — подключай свои.

### Шесть тестов фазы VALIDATE

Первые три проверяют, что агент **отвечает правильно**: поднялся и попал в
формат · триггеры уводят к нему своё и не уводят чужое · память живёт, а не
задекларирована. Механика — `skills/build/references/behavior-eval.md`.

Следующие три проверяют, что он **работает, влезает в контекст и не врёт про
себя**. Механика — `skills/build/references/acceptance.md`.

| Тест | Что ловит |
|---|---|
| **4. Боевая приёмка** | скилл, по которому нельзя работать: команда с неверным флагом, шаг без входных данных, гейт, требующий того, чего нет |
| **5. Бюджет контекста** | сколько агент съедает на каждый вызов — единственная проверка, которую нельзя сделать глазами |
| **6. Контракт против тела** | обещания, которых нет в реализации |

Зачем это добавлено. На реальной сборке шесть независимых ревьюеров с чистым
контекстом дали 25 жёстких находок. После починки всё было зелёное. Потом
агента прогнали **на настоящей задаче** — и он нашёл ещё 12 дефектов, которых
не увидел никто из шести. Три худшего класса: отказы, которые выглядят как
успех (проверка печатает «блокер» и возвращает код успеха; заглушка
антибот-защиты засчитывается как добытый источник).

**Ревью читает, приёмка исполняет.** Зелёные гейты значат «внутренне
непротиворечив», а не «хорош».

### Замер бюджета контекста

```bash
python3 scripts/context-budget.py <путь-к-агенту>
```

Считает постоянную часть (платится за каждый вызов) и полный такт каждого
скилла. Пороги откалиброваны по живым работающим агентам, а не взяты круглыми:

| | 🟢 | 🟡 | 🔴 |
|---|---|---|---|
| Постоянная часть | ≤3 000 | ≤5 000 | >5 000 |
| Такт | ≤8 000 | ≤15 000 | >15 000 |

Для сравнения: у отлаженного агента с шестью скиллами постоянка ~3.6к, такты
6-7к. У свежесобранного до чистки — постоянка 7.2к и такты до 54к, то есть в
семь раз дороже. Разницу не видел никто, потому что мерить было нечем.

## Известное

`bash scripts/validate.sh .` из коробки покажет ~100 broken links — это ссылки на `office/agents/*` живого офиса, в который Демиург обычно встроен. Когда подключишь Демиурга к своему workspace или соберёшь первый офис — ссылки заработают по своим местам.
